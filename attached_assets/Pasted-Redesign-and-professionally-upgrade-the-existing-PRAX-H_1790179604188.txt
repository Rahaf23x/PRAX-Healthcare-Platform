Redesign and professionally upgrade the existing PRAX Healthcare Platform without rebuilding the project from scratch.

PRAX is a smart emergency patient identification and medical information platform designed to help paramedics and hospitals access critical patient information quickly during ambulance transport.

IMPORTANT:
- Do NOT delete or break any existing functionality.
- Do NOT replace working features with mock screens.
- Keep the existing routing, logic, data, authentication, language switching, medication analysis, and patient information functionality.
- First inspect the existing codebase and understand the current structure, then improve it.
- Make the changes directly to the existing application.
- The final result must look like a real professional healthcare technology product, not a hackathon prototype.

## 1. Overall Visual Direction

Create a premium, modern healthcare interface inspired by professional medical platforms and emergency-response systems.

Use:
- Clean white and very light blue-gray backgrounds
- Deep navy for primary text
- Professional medical blue as the main accent
- Very limited red only for critical warnings
- Subtle teal/green for verified or safe states
- Soft shadows
- Large clean cards
- Rounded corners, but avoid excessive rounded/pill-shaped elements
- Strong visual hierarchy
- Plenty of whitespace
- Consistent spacing and alignment
- Professional typography
- Minimal and elegant icons

The interface should feel:
Professional
Trustworthy
Calm
Medical
Fast
Secure
Premium
Emergency-ready

Avoid:
- Excessive gradients
- Excessive animations
- Neon colors
- Cartoon-style illustrations
- Overly decorative elements
- Generic AI-dashboard aesthetics
- Crowded layouts

## 20. Visual Polish

Perform a complete visual consistency pass across the application.

Make sure:

- Buttons have consistent sizes

- Typography follows a clear hierarchy
- Headings are consistent
- Borders and shadows are subtle

## 21. Do Not Overdesign

PRAX is an emergency healthcare platform.

Speed and clarity are more important than decoration.

A paramedic should be able to understand the patient's critical information within seconds.

Prioritize:
CLARITY → SPEED → SAFETY → TRUST → VISUAL POLISH

## 22. Technical Requirements

Before making changes:
1. Inspect the entire existing project structure.
2. Identify the current frontend framework.
3. Identify the backend.
4. Identify the database.
5. Identify existing routes.
6. Identify authentication.
7. Identify existing API endpoints.
8. Identify existing patient data structures.
9. Identify the existing Arabic/English implementation.
10. Preserve working functionality.

Then implement the redesign using the existing technology stack whenever possible.

Do not introduce unnecessary frameworks or dependencies.

After implementation:
- Run the application
- Test all existing routes
- Test Arabic and English
- Test responsive layouts
- Test patient identification flow
- Test patient profile
- Test medication analysis
- Test paramedic workflow
- Test hospital workflow
- Fix all TypeScript/build/runtime errors
- Make sure the application remains functional

FINAL GOAL:

Transform the current PRAX interface into a polished, premium, production-oriented healthcare platform.
